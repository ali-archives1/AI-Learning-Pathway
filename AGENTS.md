# Communication preference

- Lead with the most important point.
- Keep replies concise, simple, and easy to understand.
- Use plain language and minimal jargon. Briefly define necessary technical terms.
- Use short paragraphs or a few bullets.
- Give enough explanation to help Ali learn, but avoid long essays unless he asks for detail.
- Never hide essential warnings, limitations, decisions, or next steps. Summarize them clearly.

# Repository safety

- Preserve existing learning evidence and certificates.
- Keep secrets, credentials, API keys, private school or family information, and unrelated personal files out of Git.
- Never delete files, force-push, rewrite published history, or change repository visibility without Ali's explicit permission.
- Verify evidence before marking a course, module, or project complete.
